## Context

**What this is:** A ~700-line C++20 limit-order-book matching engine (CodingJesus base layer). Header-only value types + `Orderbook.{h,cpp}` holding the core: `std::map<Price, std::list<OrderPointer>>` for bids/asks, `unordered_map<OrderId, OrderEntry>` for O(1) cancel via stored list iterator, and a background thread that prunes GoodForDay orders at 16:00. `main.cpp` is an empty stub — the real exercise surface is the gtest suite in `OrderbookTest/`.

**Portability findings** (I trial-compiled `Orderbook.cpp` with Apple clang 21 / `-std=c++20`):

- **One hard error, total:** `Orderbook.cpp:17` calls `localtime_s(&now_parts, &now_c)`, an MSVC-only function. POSIX has `localtime_r` with the arguments reversed. I patched it in a scratch copy and the entire translation unit compiled clean.
- `<format>`, `<charconv>`, `std::map::contains`, `<atomic>` all resolve fine on this toolchain — no C++20 gaps to work around.
- `Orderbook.h:45` uses `std::atomic<bool>` without including `<atomic>`. It compiles only because MSVC and libc++ both pull it in transitively — a latent break, one line to fix properly.
- `test.cpp` does `#include "../Orderbook.cpp"`, so the test binary already contains Orderbook's definitions. **The Makefile must not also link `Orderbook.o` into the test target** or every symbol duplicates.
- The test fixture resolves fixtures as `std::filesystem::current_path() / "TestFiles"`, so the test binary must be run with `OrderbookTest/` as the working directory.
- `test.cpp:273` uses `INSTANTIATE_TEST_CASE_P`, the legacy spelling. Homebrew ships googletest **1.18.0**, where it survives only as a deprecation shim. One-word fix to `INSTANTIATE_TEST_SUITE_P`.
- googletest is **not** installed on this machine — `brew install googletest` is a prerequisite step.

## Two latent bugs I found — flagging, not fixing today

Both are pre-existing and out of scope for "get it running," but you'll want them on the board before optimizing:

1. **`Orderbook.cpp:146-149`, `CanFullyFill`** — mixed `&&`/`||` without parentheses. Because `&&` binds tighter than `||`, this parses as `(threshold.has_value() && side == Buy && threshold > levelPrice) || (side == Sell && threshold < levelPrice)`, which is almost certainly not the intent. Clang flags it under `-Wparentheses`, so it'll surface as a warning on the first build. This is a real FillOrKill correctness bug, not a style nit.
2. **`Orderbook.cpp:42-44`** — `const auto& [order, _] = entry;` reuses `_` inside a loop that already bound `_` in its outer decomposition. Clang accepts it only as a C++2c placeholder-variable extension (`-Wc++26-extensions`).

Also worth noting for the perf phase: `CanFullyFill` iterates the *entire* unordered `data_` map and relies on price ordering that an `unordered_map` does not provide — that's both a correctness smell and the obvious first optimization target.
